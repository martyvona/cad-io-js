# Changelog

## Unreleased

- `cad-viewer` (`packages/viewer`), an interactive three.js viewer built with Vite, phase 1: glTF, GLB and three.js JSON through three.js's loaders, in a Z-up millimetre world; orthographic camera, trackball controls, zoom all, views along the axes, centring, full screen, drawing only on change at up to 30 fps; local files, URLs, drag and drop; `cad-viewer start|stop|status|open` for its dev server, which serves a content root (default `test_corpus/`), on the LAN and over https by option. See the README's "Viewer".
- `cad-viewer` phase 2: STEP files through our packages, parsed in the page and meshed by OCCT or truck in Web Workers with the IndexedDB cache, appearing part by part with their B-rep edges (edges found from triangles where a part or a three.js-loaded mesh has none); meshing settings in the page; a new file cancels meshing. `tess-workers`: `tess-workers/web-worker` (`serveWebWorker(modules)`) and `webWorkerHandle` let a bundled application give the pool its own worker entry; `./browser` entries in `tess-workers` and `tess-cache`.
- `cad-viewer` phase 3: the assembly tree (Headless Tree behind our own small interface; rows drawn only in view), with faces, edges, curves and points below parts on request; selection by click, ctrl/cmd-click, shift-click and keys; hide selected, show selected, show all (the file's hidden instances included), hidden rows greyed; a face hidden in every placement of its part.
- `cad-viewer` phase 4: picking in the 3D view (click or tap; an assembly, a part, or a face, edges or curves; hidden and cut-away things skipped), shared with the tree's selection; highlighting, optionally of all a part's placements; details (counts, triangle area, edge and curve length, "placement k of n"); zoom selected; select parent; multi-select for touch.
- `cad-viewer` phase 5: the CAD rendering style (as the cadrender prototype): Phong faces (glTF and three.js materials converted, by option), edges, N8AO ambient occlusion and SMAA, each adjustable; transparency by three.js's sorting.
- `cad-viewer` phase 6: section planes across the world's axes (position, side), cutting everything drawn and picked; hatched caps in the part's colour on closed parts, by the stencil technique.
- `cad-viewer` phase 7: a progressive web app (vite-plugin-pwa): builds precache everything, the backends' modules included, and work offline; phones and tablets: no page scrolling or bouncing over the view, panels closed at first, taps pick.
- `cad-viewer` phase 8: STEP files parsed and meshed in a worker (its tessellation pool nested in it), the scene and meshes posted to the page as they come; the page path kept as an option.
- `cad-viewer` phase 9: the README's viewer section rewritten as a guide, with building and deploying; builds carry only three.js's glTF Draco decoder (1 MB less to cache), `licenses.md` (what's bundled under which license, OCCT's LGPL included) and no build warnings; the build check serves the build below a path from a plain static server; `npm run deploy-viewer` publishes a build to GitHub Pages (the `gh-pages` branch).
- `cad-viewer`: the tree panel closed until a model loads (then open, unless closed by hand), with a handle that drags its width (remembered; a double click for the default); section planes back to their defaults, all off, for each model; the controls flush with the right edge.
- `cad-viewer`: recording and replaying sessions (the Recording folder, `?record`): timed events with pointer positions in pixels, picks and their results, controls, the camera, files (by hash), API calls; replay in the page or headlessly (`cad-viewer replay`), reporting divergences.
- `cad-viewer`: driven from outside: the view in the page's address (camera, sections, rendering, tree, hidden and selected nodes) and **Copy link to this view**; stable node paths; `window.cadViewer` (load, idle, state, apply, link, nodes, select, hide, show, views, pickAt, screenshot); `?deterministic`; `cad-viewer shot <file>` renders a file headlessly to PNG, with the page's state as JSON.
- `tess-occt`: our own patches to OCCT (`packages/tess-occt/occt_patches/`, applied by `build-occt.sh` to a worktree of the pinned checkout, named in the backend's version); the first, `0001-brepmesh-cone-seam-pcurves`, fixes OCCT 8.1 leaving a cone face unmeshed when its seam's pcurves slope by the slightest amount (`conical-surface.step`).
- `cad-viewer`: picking fixed: another part's edge within 4 pixels no longer beats the face under the pointer (on the bicycle at full view, 23% of clicks on parts picked a neighbour); a browser check compares picks with an ID render over a grid of points.
- three.js JSON: the root's matrix turns millimetres and Z up into metres and Y up, as glTF's root node does, with extras or without; with extras the root's `userData` adds `up: 'z'` beside `unit: 'millimetre'`, both describing the frame below the root. Before, the file was in millimetres with the source's axes. `cad-scene` exports the matrix as `Y_UP_METRES` (`export-gltf`'s `ROOT_TRANSFORM` and `export-threejs`'s are it).
- `cad-scene`'s `sha256`: Web Crypto's SHA-256 where it exists, else our own (`sha256Js`), with the same digests; the backends' module hashes and the cache's keys use it, so both work in pages that aren't a secure context (plain http on a LAN), where `crypto.subtle` is missing. Keys and versions are unchanged.
- glTF compression: Draco (`KHR_draco_mesh_compression`) by default, meshopt (`EXT_meshopt_compression` with `KHR_mesh_quantization`) or none by option (`stepconv --gltf-compression`, `--gltf-draco-bits`; the exporter's `compression`, `dracoPositionBits`). With Draco and extras, faces are a `_FACE` vertex attribute instead of index ranges. `gltfDocument` is now async.
- glTF instancing by option (`stepconv --gltf-instancing`, the exporter's `instancing`): each part placed more than once is one node under the root with `EXT_mesh_gpu_instancing` (required), out of the assembly tree; with extras, its `extras.instances` names each instance's place in the tree.
- Assembly nodes with nothing to draw beneath them are left out of glTF and three.js output (`stepconv --keep-empty`, the exporters' `keepEmpty`, keeps them); `cad-scene`'s `pruneView` does it for any export view.
- Extras off by default in every exporter (`stepconv --extras`; the exporters' `extras`): glTF `extras`, three.js `userData` and 3MF's `cadio:path` metadata are written only on request.
- Documents: PDFs of the Markdown documents with Typst (`scripts/md2pdf.sh`, which fetches a pinned Typst with `scripts/fetch-typst.sh`) instead of pandoc and LaTeX; the README's diagrams are Mermaid flowcharts; every Markdown document has `#` for its title and `##` for its sections (the tutorial's headings moved down a level).
- The default time limit per part is 60 s instead of 120 s (`stepconv --timeout`, `tess-workers`' `timeoutMs`).
- `corpus_checks/backend_speed.ts`: truck against OCCT, tessellation time over the corpus as `stepconv` runs them.
- `stepconv`: `--angular` renamed `--angular-deflection`, `--edges` and `--curves` renamed `--with-edges` and `--with-curves`, `--gltf-unlit-lines` renamed `--unlit-lines` (accepted for three.js too, whose lines are always unlit); `--gltf-no-edges`, `--gltf-no-curves`, `--gltf-no-points` and `--gltf-faces-only` removed (`--with-edges` and `--with-curves` choose what's written).
- `tess-occt`: `init({glue, wasm, version})` loads a host's own OCCT build (one that links `occt_tess.cpp`; `third_party/README.md` says how to make one), by URL, bytes or compiled module, and checks it has the wrapper's exports. `tess-truck`: `init({wasm})` also takes a compiled module, and a `version`. A compiled module needs a `version`, which names it in cache keys.

- Every tracked text file is ASCII, source code included (comments, messages, test data as escapes), checked by `test/ascii.test.ts`. Semantic JSON unit names are joined with `.` instead of a middle dot (`newton.metre`). Long identifiers in Markdown tables are broken by hand with `<br>`.

## 0.1.0 (2026-10-23)

The first release, tagged `V0.1.0`; not published to npm (the packages run as TypeScript sources under Node 24).

- **STEP reading and writing** (`step-parser`, `step-schemas`, `lexical-json`): a two-pass Part 21 parser over bytes (a typed-array index, lazy decoding) tolerant of real-world files; a lossless raw instance model; a Part 21 writer that round-trips the 517-file test corpus with no differences; raw JSON and NDJSON with integers and reals kept apart; schema binding against AP203 (editions 1 and 2), AP214 and AP242 dictionaries generated from EXPRESS, with value checks; semantic extraction of the product structure and placements, units, styles, layers and validation properties; per-part subsets.
- **The scene model** (`cad-scene`) and the **STEP importer** (`step-import`): components and occurrences with instancing, parts per shape representation, millimetres, materials resolved from styles (per face, per instance), layers, external references; names recovered from generic ones; diagnostics for dangling references.
- **Tessellation:** the per-part `Tessellator` interface with face, edge, curve and point ids; backends on our own WebAssembly build of OCCT 8.1 (`tess-occt`, LGPL-2.1) and on truck (`tess-truck`, with workarounds for its failures on real files); a worker pool with timeouts and recycling (`tess-workers`); a cache in memory, a directory or IndexedDB (`tess-cache`); meshes repaired in memory (degenerate triangles dropped, inside-out shells turned over).
- **Export:** the export view (looks, material groups, instance transforms), and exporters to three.js JSON (`export-threejs`), glTF and GLB (`export-gltf`, with glTF-Transform) and 3MF (`export-3mf`, with fflate).
- **Command-line tools** (`cad-io-cli`): `step2json` (raw, NDJSON or semantic JSON) and `stepconv` (three.js, GLB, glTF or 3MF, with OCCT or truck, workers and an optional cache).
- **Tests:** 193 package tests, and 25 corpus checks over 517 files against OCCT and against each output format's own reader or validator.
